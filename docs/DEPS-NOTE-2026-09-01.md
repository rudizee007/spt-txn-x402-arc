# Dependency note — 2026-09-01

`go.mod` pins `golang.org/x/crypto v0.52.0` (indirect, via go-ethereum). That
version is the exact lower bound of the fixed range for thirteen 2026
advisories against `x/crypto` (every release `< 0.52.0` is affected and
0.52.0 is the first that is not), so this tree sits on the boundary with zero
margin — the `x/sys` coupling recorded
in `spt-poc/docs/DEPENDENCY-ADVISORIES.md` (pinning `x/sys` below 0.45.0
silently forces `x/crypto` back to 0.51.0) would re-open all 13 without any
line in this file changing. None of the affected packages (`x/crypto/ssh`,
`ssh/agent`) is imported by `settle/evm`, so this is exposure-by-graph rather
than a reachable call, but the pin should not stay on the edge. The maintainer
should run, natively and with network access (this review environment has
none, and `go.mod` was deliberately not edited by the review):

```sh
go get golang.org/x/crypto@v0.55.0 && go mod tidy
```

and re-run `govulncheck ./...` afterwards so the advisory ledger records the
new baseline.
